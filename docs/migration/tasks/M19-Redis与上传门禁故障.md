# M19：Redis与上传门禁故障

父片M19，关联FR09／11、NFR06—08及T51-C09。依赖M11／M12／M18与M02的Redis条件；Vue入口、M20全入口与正式切流未迁移。

本轮功能：限流窗口迁移到Redis原子计数，故障、重启或键淘汰时不放开新收费／生成入口；已提交收尾继续。

- **旧窗口导入**：启动时把PG仍有效的`auth_rate_limits`窗口原样写入Redis（`SET NX`，不增加不减小计数），并在PG影子表记录窗口。
- **原子计数**：Redis Lua脚本一次完成`EXISTS`／`INCR`／`PEXPIRE`，命名空间含迁移环境；PG影子记录最近计数与截止，用于丢失检测。
- **故障关闭**：Redis断连、命令异常或键丢失但PG影子窗口仍有效时，写入PG故障闸门并返回503 `RATE_LIMIT_UNAVAILABLE`；登录／注册、支付结账、视频prepare／提交等新入口保守关闭，不静默按零计数。
- **已提交收尾**：已登录本人读取、视频状态查询、提示词状态和独立Worker保存继续；`suny`业务不限次状态不因Redis门禁改成次数限制。
- **上传全局槽**：视频prepare／提交的全局槽由主库`upload_slots`条件租约控制，Redis不是唯一互斥依据；第二个进程返回503 `VIDEO_BUSY`。

验收：随机临时schema＋真实PG／Redis＋TCP代理故障注入；23项检查覆盖旧窗口导入、原子30次上限、断连时登录／结账／生成503与读取继续、Worker收取继续、重连后故障窗口仍保守、重启丢键与淘汰不放开、显式清窗后恢复、上传全局槽跨进程互斥。Maven verify及M13／M14／M16／M17回归同批通过。

边界：未接真实支付／模型预算；未做真实云Redis ACL／TLS／持久化配置验收；未接Vue，未切换8787／8788。证据见[报告](../../reports/2026-10-29-M19-Redis与上传门禁故障.md)。
