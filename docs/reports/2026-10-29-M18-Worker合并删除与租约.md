# M18 Worker合并删除与租约（2026-10-29）

关联：FR11／46、NFR06—08；T51-C07／08／10；任务卡[M18](../migration/tasks/M18-Worker合并删除与租约.md)。基线：M17提交`f39159e`。本片只完成Java隔离切片，Vue入口、M19 Redis门禁与G2未完成。

## 1. 本轮改动

- `WorkerService`：认领使用`FOR UPDATE SKIP LOCKED`短事务并递增租约代次；下载临时文件带代次；发布前同事务核对task／owner／generation／未过期租约与作品状态；删除竞态时取消保存任务、清除临时文件并补cleanup；capturing超时条件转为saving并保留`PARTIAL_CAPTURE`，capture-finish拼接已确认分片；空片段failed／`CAPTURE_EMPTY`。
- fixture新增`worker-state`／`video-job`／`works-age`／`works-delete`，支持真实PG故障注入。
- 新增`java_worker_lease_contracts.py`：真实PG＋两个独立Worker进程＋可控延迟合成供应商。

## 2. 实际验证

环境：一次性Docker PG15、Redis6；存储为脚本创建的独立临时目录，结束删除。

| 命令 | 结果 |
| --- | --- |
| `./mvnw.cmd -B -ntp verify` | BUILD SUCCESS，54项JUnit通过 |
| `python -m scripts.java_worker_lease_contracts` | PASSED，15项检查；临时schema与存储清理 |
| `python -m scripts.java_worker_contracts` | PASSED，20项（M17回归） |
| `python -m scripts.java_video_contracts` / `java_works_contracts` | PASSED，48／85项（M14／M15回归） |

专项覆盖：两个Worker同时竞争同一video-save任务，第一个下载慢、租约过期后第二个以新代次完成；任务`leaseGeneration≥2`、`attempts≥2`，只发布一份精确字节的`result.mp4`，旧代次临时文件被清除；下载中直接写删除墓碑后作品保持deleted、保存任务cancelled、cleanup succeeded、无结果文件；超过200ms阈值的capturing作品部分保存为ready并保留`PARTIAL_CAPTURE`，仅一个capture-finish任务且内容等于已确认分片；全程供应商POST计数0。
