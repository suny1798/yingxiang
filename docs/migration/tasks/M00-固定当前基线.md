## 执行步骤与观察入口

1. 运行只读Git检查，记录HEAD、分支、工作树、已有未提交／未跟踪文件；给用户原有改动单列归属，不做stash、reset或强制checkout。
2. 核查8787／8788等实际端口和服务启动目录；确认是否为开发模式监视当前源码，决定直接在原目录开发还是需要临时worktree。此处先记录方案，不重启／中断服务。
3. 生成脱敏资产清单：源码／锁文件／OpenAPI指纹、环境变量名称、数据库revision定义、备份／私有媒体路径边界及恢复命令来源。正式数据与secret不进入Git。
4. 对照当前README中的实际脚本建立隔离验证入口。测试只连接临时库和HTTP替身，禁止生产／真实供应商请求；先确认测试隔离配置，再运行适用的原测试／类型／构建。若构建会与现有服务共享产物，先隔离，不在运行目录直接覆盖。
5. 检查现有备份工具是否包含媒体；没有则记录缺口并为M02建立“数据库＋媒体联合快照／恢复”验证任务。M00不把检查脚本存在当作恢复演练完成。
6. 保存原版本源码／构建恢复产物的定位和校验值；是否创建基线提交依用户审核授权。未获授权时使用受控本地快照并记录“未提交”，不阻断无须提交即可开展的M01准备。
7. 输出报告，更新05中M00结果及M01／M02可领取条件。

## 完成标准

- 当前HEAD／文件指纹、工作区原有改动、实际运行目录／端口均可定位；没有覆盖用户修改。
- 依赖锁、合同、私有数据与媒体／提示词历史的边界有清单，配置不泄露值。
- 当次验证用真实命令、目录、退出码和摘要记录；未执行项有具体依赖，不引用旧测试数量冒充通过。
- 已确定安全开发位置与恢复产物，Git未授权时明确未提交；DB和媒体恢复缺口转M02，不伪报可恢复。
- Spec和Standards分开自检或审查，明确是否独立；报告不只写“已检查”。

停止条件：发现工作区归属冲突、运行服务会被构建覆盖、测试可能连真实密钥／库、备份路径落入可清理产物目录时，停止相关动作，保留证据并继续不依赖该条件的清单工作。不得为修基线修改预算、权益或unknown。
