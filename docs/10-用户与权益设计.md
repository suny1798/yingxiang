## 1. 当前建议

先完成账号、一次免费体验、权益记录与会话归属，再接真实支付。账号与权益不依赖特定支付渠道；没有可用收款渠道时不显示可购买按钮、不生成真实收款订单。保留现有本机开发体验，不因设计草案擅自切换正在使用的入口；正式账号模式上线后，必须关闭或隔离可绕过权益的/api/studio开发签发接口。

优先手机号验证码登录，首次验证通过自动注册，不另设注册步骤。短信服务尚未选定，须核实个人身份可申请的签名、模板及实际发送能力；不能把“面向中国大陆”视为短信服务已可用。若暂不具备条件，建议讨论邮箱验证登录作为前期方案，而非添加万能验证码、假短信或手机号密码绕过验证。登录方式由独立身份表关联稳定userId，后续绑定手机号不重新赠送免费体验。

首版不做月费无限使用。建议采用预付体验包，最终选择次数包或时长包及售价，待成功率、真实计费和可见画面时长核实后确定；暂不在页面标注未经核算的价格或保证15秒完整生成。

## 2. 免费体验规则（建议待确认）

- 一个符合条件且已验证的账号有且只有一次新用户免费权益，不是每日一次；建议先沿用当前最多15秒连接窗口。它包含令牌签发与建连，不能宣传为完整15秒生成画面。
- 免费指用户无需支付，供应商成本由项目承担；与此前开发测试预算分开核算，开放前须配置活动总预算、每日发放上限及停发开关。
- 选图、处理图片、阅读说明、相机拒绝或仅登录不消耗免费权益。相机实际就绪后，再由服务端在数据库事务中锁定权益并创建业务会话。
- 尚未调用上游且明确失败/取消，可以幂等释放；签发成功后标记权益已使用。上游超时、返回异常或结果不确定进入待核查，不能立即返还并再签一枚。进程在事务提交与外部调用间崩溃也按保守恢复规则处理。
- 客户端首帧、耗时及结束事件仅为体验观测，不能单凭客户端声称“未出画”自动恢复无限次数。真实失败可通过供应商记录或人工核查补发独立补偿权益；补偿不改写原消耗记录。
- 账号免费一次不等于自然人免费一次。手机号也不能完全防止多号；按账号、来源风险与活动总预算限流，必要时采用内测白名单。不以设备指纹作为唯一身份，不仅靠IP一刀切拦截共享网络。

## 3. 页面与交互

沿用现有浅色与莓果红风格，用户入口放在顶部右侧，账号中心不挤占主创作画面。

| 状态/位置 | 内容与操作 |
| --- | --- |
| 未登录 | 顶部“登录”；可选图与阅读说明，开启前要求登录，登录不自动开启相机或模型 |
| 登录框 | 手机号、验证码、发送倒计时、发送/校验失败；用户主动确认账号条款，云端媒体确认单独保留 |
| 新用户 | “免费体验1次”；开启前明确本次使用免费权益及时限 |
| 体验预留中 | “正在准备体验”，禁止同账号其他标签页重复占用；取消可见且清理媒体 |
| 免费已用且无付费权益 | “免费体验已使用”；支付未开放显示“付费功能筹备中”，不渲染假收款码或假支付成功 |
| 未来有付费权益 | 显示剩余额度及本次将用额度，用户主动开启；不默认自动续费或自动追加连接 |

建议初期只实现登录、权益摘要和使用记录；资料编辑、头像上传、会员等级和营销邀请不进入本工作包。注销后的订单/权益留存与免费资格去重需形成明确政策及用户说明，不能承诺删号重注册可再次免费。

## 4. 服务端与数据

继续使用现有Next.js BFF，PostgreSQL持久化账号与权益。Redis作为共享验证码、频率限制及短租约的候选，不作为余额事实来源；所有有费用的请求仍检查数据库归属与权益。数据库、短信和鉴权库接入时再核对官方文档、固定版本，当前不引入未经选择的依赖。

| 实体 | 最小职责与唯一约束 |
| --- | --- |
| User | 稳定ID、状态、创建时间；普通用户与后台权限分离 |
| Identity | 手机号/邮箱等身份绑定及验证时间；provider+规范化标识唯一；敏感标识受保护，不以普通散列保护可枚举手机号 |
| AuthSession | 随机会话凭据的服务端摘要、所属用户、到期及撤销时间；浏览器只持HttpOnly Cookie |
| VerificationChallenge | 用途、接收方关联、到期、失败次数、单次消费状态；不记录明文验证码，不在响应/日志泄漏 |
| EntitlementGrant | trial/paid/compensation来源、用户、单位、总量与有效性；新用户活动按userId+campaign唯一 |
| UsageReservation | 会话、权益来源、预留量及reserved/committed/released/review状态；同操作幂等，同用户最多一个活动会话 |
| EntitlementEntry | 不可直接覆写的发放、预留、消耗、释放与补偿流水，关联原始来源，避免单改余额 |
| TryOnSession/TokenIssue | 用户归属、截止及签发尝试；沿用短TTL、固定模型/Origin、禁止自动重连；不存令牌正文 |
| Order/PaymentEvent（后续） | 服务端商品快照、人民币分、用户、渠道、状态、唯一渠道交易号/事件号；不靠前端状态发权益 |

使用数据库唯一约束和行锁/条件更新，保证两个标签页、并行请求及重启后都不能拿两次免费权益。余额、流水、预留状态变更须在同一事务完成。外部供应商调用不放进长期数据库锁；用已提交的意图和保守未知状态处理跨系统失败。

Cookie建议HttpOnly、生产Secure、SameSite=Lax，服务端逐请求验证身份与会话归属，不能只隐藏按钮。变更请求做Origin/CSRF防护；登录、发送验证码、签发均限流。验证码发送失败亦需计入防刷与费用观察。手机号、验证码、Cookie、完整支付通知及SDK诊断对象不进入日志。

## 6. 个人开发者的支付边界

截至2026-10-23，微信官方PC网站支付接入指引列出个体工商户、企业等主体及营业执照材料。本项目没有这些资料时，不能把直接接入微信Native写成已具备条件。

支付宝官方帮助仍列有个人账户当面付及经营场景材料，另有当面付签约页要求营业执照。这些资料不能证明个人线上AI服务已获准接入：需以真实主体、实际网站/服务类目、所申请产品和当前审核结果核实。不因“个人收款码可以收钱”就推断有网页支付API、自动通知或适用业务权限。

当前建议支付状态为disabled，预留订单与权益接口。若未来通过适用产品审核再接入；也可在准备长期运营时评估取得适合的经营主体，实际产品能力仍取决于审核。第三方平台亦需核对个人卖家、中国大陆结算、AI在线服务类目和退款条件，不能假定平台能自动解决这些依赖。2026-10-23进一步核对了微信普通商户、微信小微、支付宝当面付、第三方服务商及海外MoR的公开条件与费率，结论与推荐路线见[支付收款方案调研](reports/2026-10-23-支付收款方案调研.md)：个人长期主通道仍需个体工商户，第三方仅可小额内测，海外MoR固定费不适合6.9元级单次包。

未来上线支付必须以服务端验签通知或官方查单为准，重复回调只发一次权益；退款、拒付与已消耗权益需关联原订单并留账，先做完整方案再开放真实购买。此阶段不设置个人收款码监听、截图自动认款或伪支付，也不以“赞助”名称替代实际收费订单。

## 9. 快速本机版本的实际选择

用户授权先由后端保存、数据库后续接入。本轮采用用户名密码登录，使用Node内置scrypt加盐摘要；不冒充手机号验证。会话只在服务端存摘要，Cookie为HttpOnly、SameSite=Lax、7天；固定HTTP本机开发例外，当前接口拒绝外部Host/Origin。文件仓储AccountStore集中管理用户、会话及体验记录，为后续数据库替换保留业务边界。

数据路径frontend/.cache/accounts/store.json；独占store.lock、串行读改写、临时文件sync后rename替换；超时不抢锁、损坏文件不重建空库。意外宕机留锁时先停服务、备份并检查store.json与临时文件，确认无运行进程持锁后由开发者人工处理store.lock；不可删账号库解锁。只适用于本机、小量账号，不是分布式事务或加密数据库，需妥善备份。

无需数据库、短信或新增依赖。每账号一次免费权益：检查通过后在调用上游前写review占位；令牌取得后used；上游失败/超时保持review，客户端观测不恢复次数。不采音频、不保存媒体。签发入口必须登录且有权益，观测检查用户归属，原单机不限次数入口不再可匿名使用。尚无自动补偿、付费额度、密码找回、注销、多因素或手机号验证。

2026-10-23为个人测试账号增加本机配额字段：store.json的quotas按userId配置总次数（默认1，仅接受正整数，上限1000），剩余次数=配额−已提交连接数，review同样占用配额。该字段只能手工修改本机文件，未开放注册或API入口；公开规则仍为每账号一次免费体验，不因测试配额改变定价或宣传文案。当前测试账号suny配额100，已有1次记录，剩余99次；关闭服务后修改或改代码后需重新构建并重启才会加载。

用户名可重复注册不同账号，免费规则仅账号级，不能用于公开拉新；现有本机限制保持，不公开部署、不自动启动模型。登录/注册全局60次/15分钟、单账号10次/15分钟，注册20次/小时，计数保存在服务端文件并跨重启保留；这是单机防误操作/简单防刷，不是生产风控。

未来迁移需导入稳定userId、密码算法参数/摘要、权益与历史，不重新发新用户权益；会话可统一失效要求重新登录。支付仍disabled，不把本地文件状态包装成已收费订单。免费15秒为本机快速版参数，包含建连，并非保证完整15秒画面。

## 11. 按档连接次数

FR21/T21将运行档位统一15秒、30秒、1分钟。旧quotas/trial仅针对15秒，普通新账号依旧一次；durationQuotas仅由后端数据维护，分别发放30/60秒总次数，不共享余额或自动赠送。attempt新增durationSec；历史无该字段视为15秒，不重置权益。账户返回各档总次数及剩余次数，个人中心与记录同步显示。

后端在文件锁内按所选档位检查并写review，签发成功转used，未知保留review；既有测试账号15秒配额不变。未授权改参在供应商调用前拒绝，客户端不能注册/修改长时权益。当前仅具备本机手工发放及消费工程，真实支付、收费发放和长时模型效果仍待验收；参数及维护边界见07第16节。
