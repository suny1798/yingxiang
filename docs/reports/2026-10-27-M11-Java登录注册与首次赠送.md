# M11：Java登录、注册、退出与首次赠送

日期：2026-10-27；关联[任务卡](../migration/tasks/M11-Java登录注册与首次赠送.md)、FR09／13／14、NFR06—09、T51-C01／03／04／11的Java侧范围，状态以[05](../05-开发任务与验收.md)为准。

## 实现与兼容

新增POST /api/account/register、login、logout的Java实现；正式配置默认auth-enabled=false、维护true、数据源只读，当前FastAPI／前端入口未切换。测试通过显式参数只在带所有权标记的随机PG schema中开启写入；未向yingxiang_migration写入合成账户，未导入真实账号。

密码沿用scrypt N16384／r8／p1／dkLen64，salt字符串本身作为UTF-8，不作hex／Base64解码。Bouncy Castle bcprov-jdk18on固定1.86，已核对Maven Central并实际打包。未配对UTF-16代理项按Node／Python规则替换U+FFFD；密码长度按UTF-16单元计算。恒定时间比较使用MessageDigest.isEqual。scrypt在数据库事务外执行，单JVM最多2个并发推导，等待最多2秒，避免持锁做昂贵计算。

用户名沿用3—24位ASCII字母／数字／下划线并规范小写，密码8—128个UTF-16单元；请求必须为JSON对象且恰好username／password两个字符串字段。保留4096字节上限、严格UTF-8、拒绝尾随JSON及原有错误结构／文案。原Spring Security无状态链继续使用，CSRF仅对三条账号写接口复用前置精确Host／Origin／跨站保护，其余保护未全局关闭，不新增旧客户端必填token。

注册在同一短事务中插入用户、15秒一次免费grant、唯一来源流水和会话；用户名或来源冲突整个事务回滚，不补送。登录重新锁定用户行检查当前摘要／停用，再创建会话，登录不新增免费权益。退出仅撤销首个有效Cookie对应的会话，并按旧格式清Cookie，不要求Redis可用。

Cookie保持yingxiang_session／64位小写hex／HttpOnly／SameSite=Lax／Path=/／Max-Age604800，配置public-origin为https时加Secure；数据库只存SHA256摘要，7天到期，不发JSESSIONID或Basic挑战。Secure测试校验模拟HTTPS来源下的Cookie格式，不代表HTTPS入口已部署。

## 限流与事务

限流仍由PG的auth_rate_limits持久保存：全局60／15分钟、单账号10／15分钟、注册20／小时，保留旧版短路顺序和计数语义（合法形状的尝试都会计数，失败也不回滚）。PG UPSERT原子递增／重置窗口，同一全局行按固定次序串行化后续窗口更新，跨实例不依赖Java锁。TransactionTemplate显式REQUIRES_NEW提交计数，随后才查账号、做scrypt或进入注册事务。

注册／登录前用Redis PING确认可用，故障返回受控503且不开放无限流；真实计数不依赖Redis键，所以丢键不让窗口归零。此片没有执行Redis脚本、窗口迁移、ACL写权限或M19共享缓存验收；属于已验证PG计数路径加Redis可用性门禁。本人读取继续不依赖Redis。

继续使用M10已接入的Spring JDBC／TransactionTemplate，尚未引入JPA映射。没有修改已应用V1、添加新表、改集群角色或现有授权。正式运行／迁移登录分离、生产最小权限仍是未完成依赖。
