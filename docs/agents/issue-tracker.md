# 映想本地任务与技能配置

日期：2026-10-27。适用：本项目使用to-spec、to-tickets、code-review等技能时的本地任务适配。

## 任务入口

当前使用同一Git仓库内的Markdown，不自动连接或发布GitHub／GitLab／Linear等外部Issue。安装技能不构成发送消息、创建Issue、PR、提交或推送的授权。

| 信息 | 唯一维护位置 |
| --- | --- |
| 产品需求和正式验收 | [主文档](../../实时虚拟试衣网页项目设计文档.md)的FR／NFR／T编号 |
| 迁移Spec、依赖及技术约束 | [16执行方案](../16-前后端技术与架构迁移执行方案.md) |
| M切片状态／阻塞／证据入口 | [05开发任务与验收](../05-开发任务与验收.md) |
| 当前切片上下文与操作边界 | `docs/migration/tasks/<M编号>-<主题>.md`；每片开工前按16模板建立，不预建大量空文件 |
| 执行／Spec审查／Standards审查 | `docs/reports/`中的实际报告，必要时同报告分栏；原始敏感输出在受保护目录 |

任务卡不再写一份会漂移的状态；引用05。技能的 `ready-for-agent` 在本项目对应“可领取”，前置满足后才置该状态。外部标签、父Issue、原技能默认 `.scratch/` 或“发布到tracker”动作在此映射到本地记录，不创建第二份工单。

## 各技能的调用边界

- to-spec：综合已有事实与决策，不把架构迁移重新写为竞争产品PRD；技术路径和验证入口写在16／当前卡，新增FR只回主基线。
- to-tickets：按可观察行为、真正依赖和验收拆分；广泛机械重构可使用expand—migrate—contract，不能为垂直切片强行双写正式数据库。
- code-review：先固定比较点和实际差异范围，再分别审查需求及工程约定；含未提交／未跟踪文件。原技能默认提交区间不足以覆盖当前工作区时，明确补充本轮文件快照与Diff。调用技能要求用户提供比较点而尚无该输入时遵循技能条件，不能假称已完成其独立Review。
- handoff：临时接续放Windows `%TEMP%`；任务和事实留项目文档，以路径引用，不保存secret或原始媒体。

现有用户指令与AGENTS优先：用户已明确授权每个功能完成并验证后按批次commit，不自动push／公开发布。正常可逆实现与验证沿已授权切片继续；不因借用六阶段而额外增加每阶段确认。
