# M09-a：Vue沙盒购买与订单

前置M03-a5价格确认、M04账号范围、M06—M08通过；当前状态只在05维护。关联FR15/16/35/45、T51-C01/C02/C04，按16附录A.1／A.3实施。沿用当前worktree/frontend，原工作区、正式入口与Nginx正式配置不切换。

## 输入与行为切片

`/pricing`保留既有三档展示、积分估算、套餐选择与确认弹窗，接入既有支付合同：GET `/api/payments/status` 读取沙盒开放状态；仅在用户确认后先复核本人，再POST `/api/payments/checkout`（`sku`、`requestId`）。

- 网络未知只提示“支付准备未完成，请到订单中核查。”，保留同一操作编号；再次确认复用原编号，不自动重试、不重复创建订单；换商品或换账号另建操作。
- 收银台跳转只接受 `https://checkout.stripe.com`；非法链接拒绝且不跳转。匿名确认只打开账号弹窗，不创建订单；登录后仍需重新选择并确认。
- 退出、换账号或卸载取消在途请求，迟到结果不跳转、不写入新账号。

新增 `/account/orders`（原PersonalCenter的orders段）：GET `/api/payments/orders` 读取本人最近订单、按秒测试权益与沙盒积分包；`?payment=returned&orderId=` 首次进入按订单编号查单，之后手动刷新只读列表。

- 订单显示沙盒方案、金额、状态、时间与编号；状态沿用既有五态文案；仅待付款／创建中提供“继续测试付款”，且必须用户显式点击才回到官方收银台。
- 查单与继续付款都只发一次请求；失败保留原列表并显示服务器提示；“返回此页不会自动认定付款”。
- 沙盒测试权益、积分包与真实生成权益隔离；正式购买保持关闭，页面不提供真实购买入口。

不新增API、数据库迁移或权益规则；不调用真实Stripe、不读取长期密钥、不购买或充值。

## 验收

- 单测覆盖：未登录不发私有请求；订单响应形状校验与固定读取错误；返回页仅首次查单、普通刷新只读列表；显式查单与继续付款的跳转边界；查单失败保留列表；换账号／卸载丢弃迟到结果。既有购买单测（未知复用编号、并发只发一次、换账号拒绝跳转、非法收银台）继续回归。
- 浏览器在1440×1000桌面，使用临时SQLite旧FastAPI、明确Stripe收银台替身与合成账号：匿名确认不建单、取消不建单、网络未知只保留一单、重试复用同单、返回页查单、查单失败、替身确认付款后显示已付款与测试积分、显式继续付款；全程不联网付款。
- `npm run check`、`npm run legacy:typecheck`、`npm run smoke`通过；既有local-studio、local-studio-tools、local-video-studio、studio-session、works-index、video-jobs、prompt-session脚本回归。

## 边界

- 浏览器中的收银台为明确替身，付款状态由仅临时库可用的合成控制端点改变；没有真实Stripe沙盒订单、真实扣款、真实到账或退款结论。
- 订单、积分包和权益都在临时SQLite内；不代表正式账本、正式用户或生产数据。
- 不切正式入口、不push；G1与入口切换由M09-b与用户授权单独处理。
