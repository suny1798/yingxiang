# M21-a：全量导入核对与恢复演练

父片M21，关联T25／T26／T51-C10、NFR06—08及G3数据切换准入。依赖M20；本片只完成离线导入工具、合成数据与正式数据只读副本演练。M21最终停写导入、M22切流、M23—M25不在本片范围。

## 1. 目标

把当前 SQLite／FastAPI 源库与 `data/users` 私有媒体，以白名单映射导入隔离 PostgreSQL schema 与独立私有卷，并形成可重复、可中断恢复、零未解释差异的核对证据。工具不新增常驻服务，不通过注册／发放／创建任务等业务接口导入。

## 2. 范围

- **源**：冻结目录中的 `yingxiang.sqlite3`（revision 0006）与 `users/` 子树；正式数据只读副本由 SQLite 一致性复制与媒体复制组成。
- **目标**：Flyway V1—V3 管理的隔离 schema `yingxiang_migration_it_<12hex>`，以及布局为 `<root>/users/<user>/works/<work>/` 的私有卷。
- **迁移表**：`users`、`auth_sessions`、`auth_rate_limits`、`entitlement_grants`、`entitlement_entries`、`usage_attempts`、`orders`、`payment_events`、`sandbox_credit_packs`、`budget_campaigns`、`budget_reservations`、`video_jobs`、`video_history`、`works`、`work_references`、`migration_imports`、`scene_access`、`admin_audit`、`admin_settings`，共19张。
- **媒体**：`result.<ext>`、`chunk-NNNNNN`、`reference-<id>.<ext>`、`prompts.json`；逐文件大小与SHA-256。
- **墓碑**：`works.state='deleted'` 行保留，禁止其目录／参考图／提示词复活。
- **限流窗口**：`auth_rate_limits` 未结束窗口原样保留；Redis 只作加速，不作为账本恢复来源。

## 3. 明确不迁移

`data/backups/`、`data/final-20261024/`、`data/integration*`、`data/real-tests/`、`data/rehearsal-*`、`data/prompt-composition-ui-*`、`data/sandbox-credit-verification-*`、`data/video-real-test-*`、`data/admin-audit/*.json`、`data/pre-video-history-manifest.json`、`data/restored-*.sqlite3`、`.env`／长期密钥、Redis 运行时键、前端缓存与构建产物、日志／临时文件。V2／V3 新增的 `background_tasks`、`rate_limit_shadows`、`rate_limit_gates`、`upload_slots` 在源库无对应数据，目标保持为空。

## 4. 工具与命令

工具位于 `backend/ops/`，版本 `m21a-1`；PostgreSQL 驱动为 `psycopg[binary]==3.2.10`。DSN 只从环境变量读取，不进入命令行或日志。

```powershell
# backend/
# 1) 源清单：revision、表/列/类型、逐表计数与规范行哈希、媒体清单与SHA-256
.venv/Scripts/python.exe -m ops inventory --source <冻结源目录> [--details <受保护本地文件>]
# 2) 只验证映射、约束、余额、unknown、订单履约与媒体计划，不写目标
.venv/Scripts/python.exe -m ops dry-run --source <冻结源目录>
# 3) 导入隔离目标；--rehearsal 才允许故障注入
$env:YINGXIANG_IMPORT_DSN = "<隔离PG DSN，不提交>"
.venv/Scripts/python.exe -m ops import --source <冻结源目录> \
  --schema yingxiang_migration_it_<12hex> --storage <临时私有卷> --batch <批次ID> --rehearsal
# 4) 逐表／逐用户／余额／unknown／订单／作品文件／提示词／墓碑核对
.venv/Scripts/python.exe -m ops verify --source <冻结源目录> --schema ... --storage ... --batch ...
# 5) 零差异后标记可切换批次（演练不用于正式切流）
.venv/Scripts/python.exe -m ops seal --source <冻结源目录> --schema ... --storage ... --batch ...
```

退出码：0成功；2用法／配置；3目标非空或批次冲突；4源异常；5核对差异；6存储失败；1其他受控失败。工具只接受 `yingxiang_migration_it_<12hex>`，直接拒绝正式 `yingxiang_migration`。

## 5. 验收

1. 合成数据覆盖19表、账号／会话、权益与流水、unknown、订单履约、积分包、视频任务、作品（ready／capturing／failed／deleted）、分片、参考图、`prompts.json`、限流窗口与墓碑；导入、重复导入、seal、核对零差异。
2. 正式数据只读副本导入临时PG与私有卷；逐表哈希、逐用户汇总、余额、unknown、订单履约、作品文件哈希、提示词、删除墓碑零未解释差异；源指纹不变。
3. 异常源（未知表、错revision、动态类型、账本不一致、订单履约缺失、缺结果、墓碑有媒体、孤儿文件、非法提示词）全部退出4且不写目标。
4. 重复导入同指纹只核验不增减；不同指纹在非空目标退出3；数据库事务中断后批次保持 `importing` 且业务表为零，重跑成功；媒体复制中断后批次为 `imported`，重跑补齐并核对。
5. 联合快照／恢复：SQLite＋媒体快照、恢复数据根、导入新PG schema＋新卷，指纹与正式副本一致。
6. 不停止／替换8787／8788，不连接正式PG／Redis，不写正式库／媒体，不调用模型／支付，不 push。
