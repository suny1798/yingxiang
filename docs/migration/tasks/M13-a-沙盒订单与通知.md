# M13-a：沙盒订单、通知与查单

父片M13，关联FR15／16／35／43—45、NFR06—09及T51-C03／04。M11／M12 Java侧已完成；Vue入口与正式切流未迁移，本片不认定M13整体或G2完成。

本轮功能：迁移旧Payments的订单预留、Checkout、本人查单、查单恢复与Webhook发放。固定SKU／积分包、同源／登录／归属、每账号每小时10次预留、同requestId幂等、同编号换方案409、creating未知单复用、23小时人工核查边界、金额／币种／账号／mode／session归属不匹配409、事件ID去重、同事务发放stripe_sandbox权益或积分包、只接受本沙盒直连非live通知。正式支付恒关闭。

实现方式：Spring JDBC＋真实PostgreSQL；Stripe通过本机合成替身HTTP验证（JDK HttpClient，API版本与参数形状按现有实现；签名按`t=…,v1=…`的HMAC-SHA256与300秒容差），不引入真实Stripe SDK、不读取长期密钥、不发外网请求。替身只在127.0.0.1随机端口运行，支付服务启动时拒绝非回环API地址。

验收：随机带所有权标记的临时schema；两个Java进程（正常运行与维护模式）＋Python标准库Stripe替身；100项HTTP／账务检查，覆盖门禁先于来源、Content-Type、非法SKU／编号、创建与复用、单次session创建、pending→paid、权益与积分包、事件重放、坏签名、live拒绝、金额不符拒绝后恢复重试、替身中断保留creating且不重复建单、限流窗口、重启后持久化。原M10—M12五个脚本同批回归通过。

边界：不真实付款／退款、不调用模型；不开放Vue入口；不修改V1；overview中video／prompt的configured／budget为M14／M16前的保守空值；Redis在本片不承载支付窗口（PG窗口沿用，M19再迁移）。证据见[报告](../../reports/2026-10-29-M13-沙盒订单与管理写入.md)。
