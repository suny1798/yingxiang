## 3. 三层状态与取消

1. **页面状态**：采用 UI 文档的 idle、imageReady、requestingCamera、creatingSession、connecting、live、updatingGarment、reconnecting、stopping、ended、error。
2. **业务会话状态**：建议 reserved → active → ended/expired；未有效使用为 abandoned。active 来自客户端播放事件时仅作运行提示，不作为可信计费依据。
3. **供应商连接状态**：由 SDK 与供应商维护；connected 不能证明画面已实际播放，业务 ended 也不能证明远端已经停止计费。

使用操作序号防止旧异步结果回写；结束先设置取消标记，再清理本地资源，最后尽力上报。图片处理、相机授权、创建业务会话与模型连接每个异步边界都检查取消。如果用户取消后服务器仍成功创建会话，应尽力结束该会话，并由服务端过期策略兜底。

禁止独立轮询式无限重连。SDK 重试仍须受业务截止时间和终态控制；令牌端点返回额度不足、已结束或停用时，应用要中止后续重连并清理，不能只依赖 SDK 对 provider rejection 的默认处理。

## 4. 时限规则与费用边界

### 4.1 三个时钟

- `deadlineAt`：业务会话创建后最多60秒的截止窗口，包含建连和重连；不承诺完整60秒生成。
- `expiresAt`：某次短期令牌能够用于建立新连接的截止时间。
- `maxSessionDuration`：供应商对该次连接允许的最长持续秒数。

此前仅使用“签发时剩余业务时长”设置 maxSessionDuration，会忽略令牌晚用。例如剩余60秒时签发30秒 TTL 的令牌，29秒后建连仍可能再运行60秒。这是基于令牌与连接时长语义的推导，不是已观测到的本项目账单。

### 4.2 首版保守设计

候选令牌 TTL 改为10秒，另留候选5秒的签发、握手及时钟余量；最终数值和供应商计时语义须通过 PoC 校准。使用服务端开始调用签发接口时的时间作保守参考，不信任浏览器时钟。

```text
remaining = deadlineAt - 服务端签发请求开始时间
connectionCap = floor(remaining - tokenTTL - safetyMargin)

如果 connectionCap < 供应商最小时长10秒：拒绝签发并结束恢复尝试
否则：maxSessionDuration = min(配置的单连接上限, connectionCap)
```

签发返回后再次检查真实 expiresAt；若预计最晚建连时间加 connectionCap 和余量超出业务 deadlineAt，则不向客户端发出该令牌，记录签发风险并停止本次连接尝试。供应商签发耗时、有效窗口及连接时长起点在实测前不能视为已证明。

该保守设计可能使一次连接早于60秒窗口结束。UI 用“最多60秒”而非“保证试穿60秒”；供应商时限结束视为正常结束，避免为延长一次体验自动另开连接。用户看到的剩余时间需要同时受业务截止时间与本次连接上限约束。

此算法约束的是单连接的预期终止窗口，不能单独约束令牌被重复使用后的总连接数或总费用。预算和并发仍需供应商侧能力验证；服务端租约与前端控制不构成账单硬上限。

每次签发记录开始时间、上游到期时间、连接上限与可能终止上界，不记录令牌正文。超时但不确定上游是否签发成功时保留风险预留，不立刻当作零成本失败。多个签发或复用的潜在费用要单列，不能只按一个业务会话的60秒结算。

### 4.3 必测边界

剩余时间正好到阈值、签发缓慢、令牌接近到期才使用、客户端时钟偏移、并行令牌申请、重复使用同一令牌、重连失败、业务结束后尝试连接。破坏性或多连接实验仅限明确预算和供应商允许的测试范围。

## 5. 数据与第三方默认行为

业务只存主文档定义的元数据。摄像头与结果流不进入业务数据库；图片只在浏览器内存与模型链路使用。结束清理媒体引用；保留本地有效服装预览供再次开始时，应区分预览生命周期和会话生命周期，刷新/离开后不恢复。

官方 SDK 文档说明默认启用遥测转发。项目默认候选配置 `telemetry: false`，实际接入核对类型并抓取网络请求确认。关闭遥测后，SDK 本地 stats 的可用性也需验证；需要的性能数据可通过独立浏览器能力采集，不承诺关闭转发后所有 SDK 指标原样可用。

媒体处理、信令、图片传输与供应商必要运行处理仍存在。关闭可选遥测不等于零第三方处理，也不能代替数据条款核实。只采集已列入白名单的状态、耗时、版本和错误类别；ICE、IP、令牌、订阅凭据等不得随完整诊断对象写入日志。

## 6. S3 需要完成的接口与数据细化

主文档第10章的接口表是概要契约。开发相关工作包之前补齐以下内容，可先在 Markdown 维护，规模增长后转为 OpenAPI：

- 每个请求和响应的类型、必填、长度、枚举、时间与数值范围；包含邀请码与 consentVersion 校验。
- 邀请兑换的原子性、会话归属、Cookie 生命周期、CSRF/Origin 验证及内部运营权限。
- 幂等键按身份与操作限定作用域；相同键及相同请求返回原结果，不重复预留；相同键不同请求返回冲突；明确保留时间与并发处理。
- 令牌签发操作号的幂等与重试语义：若短期缓存返回值，仅短暂保存在受保护内存/缓存；不永久保存正文。若不缓存，要明确重试如何避免重复签发。
- 业务状态转换、心跳 seq 去重、过期会话不可复活、end 幂等及无权限与不存在统一响应。
- 稳定错误码至少区分 INVITE_INVALID、UNAUTHORIZED、QUOTA_EXHAUSTED、CAPACITY_FULL、SESSION_EXPIRED、SERVICE_DISABLED、UPSTREAM_UNAVAILABLE；映射 HTTP、retryable 与 Retry-After。
- 数据表状态枚举、外键、唯一约束、索引、事务边界与迁移；每日额度的时区及日期边界要先确定。
- 预算金额使用精确小数或最小计费单位整数，禁止浮点累加；估算、风险预留和已对账成本分开。
- 按ADR019明确SQLite内账号/支付/权益/签发事务与外部服务调用边界，不将事务持有到网络调用结束；跨机器扩容时再评估PostgreSQL/Redis。
- 额度预留释放、租约回收、未知签发结果与账单延迟的补偿策略，删除/匿名化任务及操作记录。

这些是未完成设计任务，不是已经实现的接口能力。

## ADR022：按下载时的预览方向导出（FR29、T30）

共享useOrientedDownload/orientVideo：只在用户点击下载时读取已有Blob或同源结果；完整接收、200MB输入上限、Content-Length存在时校验长度、流错误拒绝残片。同源源文件缓存限当前源/账号；镜像关闭直接返回原文件。开启时静音video解码，以原分辨率绘制scale(-1,1)到Canvas，经captureStream(25)和MediaRecorder重新编码；优先MP4否则真实WebM，约6Mbps、64MB输出上限、90秒总处理上限。加载20秒上限；处理百分比按视频播放位置，未知duration不定进度，禁止伪造百分比。重编码可能改变压缩质量/帧率，不能称无损；不改变上传/模型输入，不消耗模型次数。

实时GeneratedRecording移除录制阶段的镜像变换，保证缓存为统一原方向；回放CSS使用当前镜像，下载统一执行上述导出。最终dataavailable收齐且video真正ended后才建立输出链接。AbortController和修订号隔离取消、换源/账号/卸载，后台主动取消，回收自建video、Canvas流、定时器及Blob URL，原模型流不受影响；下载文件对象URL留到下次下载/源变化/离开，避免立即撤销使浏览器保存失败。依据：[Canvas captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream)、[MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)。

## ADR024：实时编辑先完成组合交互（FR31、T32）

### ADR024补充：整个面板随视频尺寸调整（2026-10-24）

PreviewSurface为三个画面面板提供固定可用槽位，ResizeObserver监听槽位/操作区尺寸，视频metadata/resize和可见性变化更新源比例；从可用高度扣除操作区高度后计算视频宽高，并同时设置整张面板尺寸。默认16:9，源媒体其他比例时完整跟随源比例，contain，取消cover与演示视频缩放裁切。面板在槽位左上方排列，保持与素材栏22px正常间距，空白留在整体工作区右侧。离开时回收observer、事件和动画帧；不触碰媒体轨道、生成会话或导出逻辑。

ADR024组合居中补充：PreviewSurface从整行总宽、左栏宽及列间距推导未缩减的画面可用宽度，算出面板后将剩余宽度对半作为整个workspace的padding-inline；导航不参与组合。标题/底部按相同留白对齐，小屏单列清零留白。组件卸载清除动态留白，窗口缩放观察整行及左栏，不能用已加留白的槽位宽度反推，否则可能锁定旧宽度。

## ADR025：共享固定框架，业务内容不参与几何计算（FR32、T33）

## ADR026：账号显示跨页复用，授权仍由后端确认（FR33、T34）

SiteHeader给未知读取、登录和匿名预留同宽账号槽，主导航改为对称列定位，所有页面统一页头高度；移除studio对共享页头的局部高度/手机间距覆盖。html使用稳定的双侧scrollbar-gutter，避免从长个人中心到单屏工作区时可用宽度变化。该修复不更改业务API、会话鉴权、模型或权益。

## ADR029：两级角色与同项目管理台（2026-10-25，FR43—45/T44—46）

当前单体、单运营者体量复用Cookie会话，数据库users.role=user/admin及disabled；不引入OAuth服务、JWT角色副本、通用权限树、独立后台工程或CMS。公共账号DTO仅增role；导航作显示控制，FastAPI统一路由依赖及每次服务层读/写事务都重查数据库角色。同源写保护不变，角色降级/升级与账号暂停撤销目标会话，防缓存角色越权。0004用ADD COLUMN扩展users，避免重建其业务外键，显式CLI给既有suny授权，注册名相同不自动授权。

管理API限定白名单业务动作。真实换装grant/revoke保留账本约束，正数独立grant、负数仅逐笔回收可用余额；审计同事务、requestId全局唯一并校验操作者/目标/完整受控输入，失败回滚。设置乐观版本控制；paused状态在生成授权与预留事务内复核，不改变env预算/密钥/名单。读列表只选可公开运营字段，每页20条；订单/媒体/unknown风险不提供篡改接口。

公告为中英纯文本，由共享页头挂载组件展示可关闭浮层，不改工作区框架；公开接口只返回已发布正文。后台读写和列表全部no-store；没有任意文件、SQL或HTML执行功能。权限及审计是新增数据库运营元数据，沿用现有备份策略，不能从网页删除审计。界面英文文案随现有语言偏好，用户填写的原因/公告不擅自翻译。参考[OWASP逐请求授权建议](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)与[FastAPI依赖机制](https://fastapi.tiangolo.com/tutorial/dependencies/)。
