3. 打开[首次真实换装验证](http://127.0.0.1:8787/poc)，未使用的当前批次应提示“本轮可开始一次真实测试”及“模型组件已就绪”。状态查询和SDK初始化不访问供应商或消耗生成额度。原first-vton已使用，不能恢复；第二批使用后也保持禁止开始。

5. 允许相机、等待远端视频实际播放。先检查是否看见衣服变化、人物保留及明显失真；远端首帧播放不等同已验证换装成功。

如果页面停在等待相机授权，仍可结束；此时尚未签发令牌，也未发送媒体给模型。若已进入签发或连接阶段，不能根据没有看到画面就认定零费用。

## 3. 本地门禁及记录

代码只接受http://127.0.0.1:8787或http://localhost:8787的Host及匹配Origin，变更请求还需本机状态接口给出的随机访问凭据。没有凭据、跨站、无效JSON或非本轮告知版本都在调用上游前拒绝。禁止将此门禁当作公开部署的登录或邀请鉴权。

每个经明确批准的批次ID固定在policy.ts；在frontend/.cache/poc/中用独占创建文件占用该批唯一签发机会，刷新、应用重启或并发请求不能自动再次签发。先记录reserved，再调用供应商；失败或返回约束无法确认时记为unknown并停止。记录不保存令牌、长期密钥、图片、视频、邀请码或完整SDK对象。

观测只记录结果类别、首个远端播放耗时、供应商generationTick事件秒数、本地轨道是否结束及本机尝试编号。客户端观测不是可信账单，也不作为正式性能分位数证据。unknown不会因为客户端上报而变成已成功。

不自动删除或重置本批记录。需要重测时先核对实际用量和剩余授权，由新的明确决定生成新批次；不能靠删除记录绕过本轮限制。

## 4. 已知限制

- SDK 0.2.12的realtime.connect未公开AbortSignal参数；取消时立即关闭本地轨道、清空视频，SDK若迟到返回则立即disconnect。尚未取得客户端句柄的在途连接不能据此保证供应商立即停费，依赖请求的单连接上限并核对账单。
- retries=0约束初次连接；应用还拒绝后续apiKeyProvider请求，遇到reconnecting立即停止。底层传输的内部恢复边界仍需在真实环境验证，不能等同供应商全局并发或费用硬上限。
- 本地文件门禁仅用于本机单批实验，不实现生产身份、配额、跨实例预算或供应商令牌不可复用保障。原/api/v1真实业务入口继续503。
- 当前只提供首个换装实验，不声明已支持提示词改背景、宠物或摆件，不默认保存生成画面截图。

## 6. 首批失败与诊断修复

首次失败时本地没有签发记录。排查发现将浏览器原生fetch作为适配器实例方法调用可能触发Illegal invocation，已用闭包包装并补回归。修复后用户主动操作的一次真实测试在2026-10-23 00:33（北京时间）签发令牌，随后连接中断，未观察到首帧；客户端上报本地轨道已结束。用户反馈控制台显示最新使用时间00:33，暂未看到用量消耗，不将此写为已最终确认零费用。

SDK初次建连失败会先发disconnected再reject；旧代码提前停止导致实际拒绝原因被通用提示覆盖。现已改为初次失败交由connect拒绝处理，保留固定错误类别；已连接后的断开仍清理并禁止重连。修复通过无费用回归，尚未对真实模型再次复测。原失败缺少可恢复的上游错误类别，原因仍未确定，不凭猜测归因为余额、权限或网络。

首批记录为finished、outcome=error，次数不恢复。用户已另行批准一次诊断，按第1节执行第二批；不自动购买、充值或继续创建第三批。
