## 官方规划与账户边界

前一会话已安装 stripe@openai-curated、添加 https://mcp.stripe.com 并完成 OAuth。本会话重新加载后实际发现并调用 `stripe_implementation_planner`，没有重复安装，也没有使用备用 skills 安装流程。先调用账户列表，用户选择唯一的「映想 沙盒」，`livemode=false`。

规划器接收现有账号/文件仓储、实时换装九个一次性人民币体验包、大陆个人无商家资质、偏好微信/支付宝以及禁止真实扣款等完整条件。决策路径：Stripe only → web browser → 未证明 Managed Payments 资格 → 非发票 → 自定义站内订单集成 → hosted Checkout。返回 guide `iguide_61Vd8ejN2W1LTETsp41DguiuhE97x`；随后以 `accept=true`、终端节点 `out_of_box_hosted` 确认，返回一次性 Checkout 蓝图（创建商品价格、创建 Session、托管付款、Webhook）。本项目以服务端固定 SKU + 内联 `price_data` 实现价格快照，不通过 MCP 批量创建商品。

规划器通用建议 Link、动态支付方式、Adaptive Pricing。工程不固定 `payment_method_types`，支付方式由账户设置及资格决定；Link 可在 Dashboard 配置，本轮未代用户修改。为保持人民币订单金额严格核对，明确关闭 Adaptive Pricing，未启用自动税费、优惠券或自动续费。税务注册及正式定价需上线前单独确认。

读取 stripe-best-practices、stripe-docs 及 Payments/security 引用；官方文档通过 Stripe 文档搜索工具查询，后续使用已安装的Stripe CLI读取/checkout/fulfillment?ui=full-page，确认必须使用Webhook、并发去重与异步付款处理要求。插件内 SDK/API 表已落后于当前发布，实际查询 npm 并对照[官方 v23.0.1 发布](https://github.com/stripe/stripe-node/releases/tag/v23.0.1)，固定 `stripe=23.0.1`，API `2026-09-30.endive`，与安装 SDK 的 `apiVersion` 及类型一致。23版自身账号读取需显式传 `null`，已按安装源码/类型实现。

仅查询会话账户列表，未读取银行、客户或付款资料。MCP 的自身账户 API 搜索三次均没有返回对应操作，因此不能宣称已核实账户国家、charges_enabled 或正式开户资格；本地测试 key 配置后才可读取自身 Account，并在代码中比对预期账号。OAuth 工具连接不等于给应用配置 API 密钥。

[Stripe 全球支持地区](https://stripe.com/global)的 Payments 商户地区列表未列中国大陆；页脚大陆语言/地区入口不等于 Payments 商户开放。当前个人无商家资质与沙盒账户均不能证明正式收款资格。不得选择外国注册国家、创建公司/金融账户或承诺上线。[支付宝](https://docs.stripe.com/payments/alipay)和[微信支付](https://docs.stripe.com/payments/wechat-pay)还依赖商户地区、币种、业务类别及账户审批，本轮未验证可用性。

## 工程实现

- `/api/payments/status`：仅返回沙盒开关，正式支付恒为关闭。
- `/api/payments/checkout`：同源、登录、固定SKU、操作UUID、持久化限流与订单归属；服务端人民币分金额；固定成功/取消路径；仅接受测试key，并读取自身Account比对预期沙盒。通过Session URL跳转，不加载Stripe.js、不收集卡号。
- `/api/payments/orders`：只返回本人最近50条脱敏订单及独立沙盒权益；不返回Checkout URL、会话或用户私密数据。
- `/api/payments/reconcile`：仅本人、同源POST；服务端重新读取绑定Session核对；未知创建可使用同一订单/幂等key恢复，待付款可继续跳转。不能用浏览器传入金额/状态认定付款。
- `/api/payments/webhook`：限长原始字节、官方SDK验签/时间容差，拒绝live和Connect通知；处理completed/async_payment_succeeded/async_payment_failed/expired后，仍使用测试key查Session当前状态，核对mode/livemode/归属/metadata/金额/币种/Session唯一性。只有complete且paid才发放。
- 订单、事件去重及沙盒权益合并到现有AccountStore事务；同一锁与原子替换保证单机并发、事件重放、查单竞态及进程重启只发一次。已有用户、手工quotas/durationQuotas和未知签发记录不改写。未对真实账户文件执行支付测试或重置。
- 申请未知时保留creating，重试保持参数及幂等key；23小时后停止重建并要求人工核对（Stripe幂等记录不是永久保存）。随机字母标签从订单ID稳定派生，重启不改变请求参数。付款成功后不受迟到未付款/过期消息降级。
- 沙盒权益保存在`sandboxGrants`，不加入真实模型`quotas/durationQuotas`，不会因为测试卡付款获得实际AI调用次数。15秒免费体验、视频及提示词额度保持原规则。
- 价格页仅配置齐全后显示「沙盒测试付款」；个人中心支持订单、查单、继续测试付款和测试权益。回跳仅显示订单，不按URL发放。pricing/account加限定来源CSP，未修改真实媒体页面的网络策略。

页面状态：未配置/未登录/准备支付/创建未知/待付款/异步确认/付款失败/链接过期/已确认/核查失败。所有订单均明确沙盒，不宣称正式收费。

## 本地配置与续接

用户要求由代理创建文件后自行填写。已在**既有**`frontend/.env.local`末尾仅补齐缺少的Stripe配置项，保留其他配置，已确认Git忽略。未读取或展示其他密钥值。编辑器已请求打开该文件。

```dotenv
YINGXIANG_PAYMENTS_TEST_ENABLED=false
STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
STRIPE_EXPECTED_ACCOUNT_ID=在本机文件中已填所选映想沙盒ID
```

1. 在所选沙盒内创建测试key，优先受限`rk_test_`。代码需要Account只读、Checkout Sessions读写；内联price_data需要相关Products/Prices创建权限，以Dashboard权限说明及实际403结果核对。不得扩大到退款、转账、客户等不需要的权限。如果特定端点不支持受限key，再评估必要的测试secret key；两者都只能填在本地服务端配置。
2. 安装并登录Stripe CLI后可在同一沙盒运行：`stripe listen --events checkout.session.completed,checkout.session.async_payment_succeeded,checkout.session.async_payment_failed,checkout.session.expired --forward-to http://127.0.0.1:8787/api/payments/webhook`。本轮未安装CLI、未运行转发、未创建远程端点。将该监听器输出的`whsec_`填到本地，不能把其他端点/账户的签名密钥混用。切换监听器后需重新核对密钥。
3. 配置完成再改开关为true、在frontend内重启应用。只能使用Stripe官方测试支付方式；不使用真实卡，不开放公网隧道，不启动真实AI。
4. 从价格页创建一个测试订单，完成测试付款；在/account确认Webhook发放、重复通知不增加、取消/失败不发放、刷新/查单恢复，以及其他账号看不到订单。核对同一沙盒的账户国家/资格及支付方式，不把沙盒成功当成live资格。

关闭开关会停止新的Stripe调用/通知处理，仍可读取已有本人订单；已收款但通知暂未处理的情况需重新打开沙盒并重放/查单，不删除记录。
