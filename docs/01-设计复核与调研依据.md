# 设计复核与调研依据

复核日期：2026-10-22。范围：项目目录中的两份 Markdown；不处理 Word。

## 1. 复核结论

现有设计可作为需求与技术基线，已经覆盖 FR01—FR12、NFR01—NFR09、状态机、控制流和媒体流、接口、数据、额度、测试及费用。当前缺少的是阶段执行规则、可复现的验证结果、完整原型与细化后的实现契约，尚不满足直接声明“开发准备完成”的条件。

本次检查是文档审查与官方资料核对，没有运行应用、连接摄像头、调用付费模型或取得账户配额和账单。因此不能认定模型在目标网络可用，也不能确认性能目标已经达到。

## 2. 发现与处理

| 编号 | 发现 | 本次处理 | 后续验证 |
| --- | --- | --- | --- |
| REV01 | 单份长文档混合需求、设计与计划，缺少进入下一阶段的条件 | 增加统一流程、文档入口和协作约定 | 后续任务是否按条件完成 |
| REV02 | 第14章从 PoC 直接进入页面开发，原型及契约收敛不够明确 | 改用 S0—S7，原型与 PoC 并行，开发前收敛设计 | 可交互原型和 S3 契约仍待完成 |
| REV03 | 第4章只有简略布局，未覆盖邀请码、告知、额度及全部页面状态 | 补充低保真线框和状态交互表 | 可用性走查、视觉设计与浏览器原型 |
| REV04 | 非功能指标有目标，缺少统一计时点、样本分层与实验记录 | 增加 PoC 及评估协议 | 取得真实结果再判定 |
| REV05 | 原令牌方案只限制连接时长为“签发时剩余秒数”，忽略令牌可以晚些使用 | 补充令牌窗口、时钟余量及保守时长计算 | 供应商实际接受窗口与停止时间 |
| REV06 | 不采集业务媒体不等于没有第三方遥测 | 补充 SDK 遥测设置与网络检查 | 默认关闭转发后，本地指标能力需单独验证 |
| REV07 | 60秒体验与60秒业务截止窗口的含义不清 | 明确首版为最多60秒业务窗口，含建连与重连，非保证60秒生成 | UI 文案和实际时间一致 |
| REV08 | 接口表、数据字段和错误示例不足以直接实现全部契约 | 明确 S3 需补齐状态、唯一约束、错误映射与幂等规则 | 契约测试与迁移验证 |
| REV09 | 20段效果测试与100次建连是不同目的，不能混作一个样本 | 分开质量样本和可靠性尝试，允许记录满足两者的重叠样本 | 样本分母、费用与失败分类 |
| REV10 | 原排期以两名开发为前提，实际团队配置未明确 | 改为依赖驱动任务；保留历史工作量估算并标明适用条件 | 技术验证后重估 |

## 4. 参考当前实践后采用什么

| 参考 | 可借鉴的做法 | 本项目的落地方式 |
| --- | --- | --- |
| GitHub Spec Kit | 先明确需求，再形成计划和任务并实施 [R1] | 用现有 Markdown 实现需求—设计—任务—验收关联；暂不安装工具 |
| AWS GLOE | 把 PoC 到生产视为分阶段过程，持续评估非确定输出 [R2] | 独立记录效果、工程行为和运行成本；无需引入整套云平台 |
| Microsoft AI 工程清单 | 明确指标、基线、可复现的实验及生产监控 [R3] | 固定评估集，记录版本和失败样本；首版无训练流程 |
| GOV.UK 原型实践 | 用线框及交互原型尽早发现用户流程问题 [R4] | 先验证上传、授权、等待、恢复和结束，再做最终视觉 |

这是针对实时视觉生成场景的适配：不照搬 LLM 的问答正确率、RAG 检索指标或自训练模型流程。项目自己的阶段编号、交付物和阈值是工程决策，并非来源强制要求。
