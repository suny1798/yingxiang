# 支付收款方案调研（个人开发者 · 中国大陆）

日期：2026-10-23
状态：调研结论，未接入任何真实收款，未创建商户号或订单。
关联：PAY01/PAY02、FR13—FR18、docs/10 第6节、docs/11。

## 1. 结论先行

1. **财付通/微信支付没有“个人网页收款 API”。** 微信支付普通商户的 PC 网站接入材料明确要求个体工商户或企业营业执照；无营业执照的“小微商户”只能由服务商进件，且官方限定线下行业，**明确不支持直播、游戏等线上行业**，线上 AI 服务不在支持范围。
2. **支付宝“当面付”个人账号可以申请基础版，但有明显上限。** 个人无营业执照可开，单笔 ≤1000 元、单日 ≤5 万元，需经营地址与经营场景照片；官方定位是线下扫码，把网页订单转成二维码收款属于擦边使用，存在场景复核风险。
3. **个人开发者最稳的长期路径是注册个体工商户。** 多数地区可线上免费办理，1—3 个工作日；之后可申请微信支付普通商户（Native/JSAPI）和支付宝当面付或电脑网站支付。费率约 0.38%—0.6%，官方回调、T+1 结算到个人银行卡，是唯一可持续、可对账、可退款的正规组合。
4. **过渡期可用第三方服务商（如 XorPay）或爱发电 Webhook 先收小额内测款，但不应作为长期主通道。** 第三方多借用“微信小微 + 支付宝当面付”通道，个人限额低，线上虚拟服务与微信小微政策冲突，存在被风控、关停或资金延迟的风险；爱发电更像赞助/内容平台，抽成高、账单呈现不适合正式商品。
5. **海外 MoR 适合海外用户，不适合当前低价国内订单。** Creem、Paddle、Dodo 都接受中国大陆个人，但固定费（$0.4—$0.5/笔）对 6.9 元的单次体验包抽成接近一半；Polar 不支持大陆提现，Stripe 不支持大陆个人直接开户。
6. **现阶段继续把支付保持为 disabled 是正确状态。** 先完成订单、权益、回调幂等与 Mock 回归，等主体与通道审核通过后再做小额真实联调；不要在未审核前展示可购买按钮。

## 3. 费用测算：为什么海外 MoR 不适合当前定价

当前拟定价格最低为 15 秒 1 次 6.90 元。按单笔 6.90 元估算：

| 通道 | 单笔成本 | 占售价比例 |
| --- | --- | --- |
| 微信/支付宝官方 0.6% | 约 0.04 元 | 0.6% |
| XorPay 综合约 1.0%—1.6% | 0.07—0.11 元 | 1.0%—1.6% |
| 爱发电约 6% | 约 0.41 元 | 6% |
| Creem 3.9% + $0.40 | 约 3.2 元 | 约 46% |
| Paddle 5% + $0.50 | 约 3.9 元 | 约 57% |

结论：**客单价低于 50 元时，MoR 的固定费会吃掉大部分毛利。** 海外 MoR 只适合高客单价套餐、订阅或海外定价；国内低价体验包应走官方通道。

## 4. 推荐路线

### 阶段 0：现在（不产生费用）

- 支付保持 disabled，不展示可购买按钮，不创建真实订单。
- 服务端先做与通道无关的订单/权益抽象：商品快照、金额（分）、订单状态机、回调事件表、幂等键。
- 用 Mock Provider 覆盖：签名失败、金额不符、重复回调、乱序回调、查单补偿、退款。
- 现有 `AccountStore` 可扩展 `orders` 与 `entitlements`，继续使用文件锁事务保证“同一订单只发一次权益”。

### 阶段 1：内测收费（建议 1—2 周准备）

1. 注册个体工商户（线上办理，经营范围覆盖“互联网信息服务/技术服务/数字内容”等；具体以当地登记口径为准）。
2. 开通微信支付普通商户，申请 Native 支付；准备已 ICP 备案的域名。
3. 开通支付宝当面付（个体户可申请不限额度版本）或电脑网站支付。
4. 配置 HTTPS 公网回调地址，先用 1 分钱真实订单联调，再开放小额套餐。
5. 同步准备用户协议、隐私政策、退款规则、客服渠道与发票说明。

### 阶段 2：稳定运营

- 评估升级企业主体、对账自动化、退款与争议处理。
- 若做海外，单独评估 Creem/Dodo，并为海外设置更高客单价，避免固定费侵蚀利润。

### 明确不做

- 个人收款码挂机、手机监听、V 免签、截图认款。
- 二清或“大商户”代收（资金经第三方池子周转）。
- 用个人静态收款码收远程经营款（不符合收单管理规定）。
- 代注册 Stripe/Paddle 账户或借用他人主体。

## 5. 技术实现要点（对接任何通道都适用）

### 5.1 数据模型

```text
Order
  id            服务端订单号（唯一）
  userId        账号 ID
  productId     套餐标识
  productSnapshot  下单时的名称/时长/次数/单价快照
  amountFen     应付金额（分，服务端价目表计算）
  currency      CNY
  provider      wechat | alipay | xorpay | ...
  providerTradeNo  渠道交易号
  status        created | pending | paid | granted | refunded | closed
  createdAt / paidAt / grantedAt / refundedAt

PaymentEvent
  id            渠道事件 ID 或本地去重键
  orderId
  type          paid | refunded | failed
  payloadHash   仅存摘要，不存完整敏感报文
  receivedAt
```

### 5.2 接口落点（与现有工程一致）

- `POST /api/payments/checkout`：登录、同源校验、限流；服务端按 `pricing.ts` 计算金额，绝不信任前端金额。
- `POST /api/payments/notify/[provider]`：验签 → 解密 → 校验商户号/AppID/金额/币种 → 事务内幂等入账 → 5 秒内应答。
- `GET /api/payments/order/[id]`：只允许本人查询；返回状态，不返回密钥或完整回调报文。
- `POST /api/payments/refund`：仅本机管理员或后台任务；关联原订单，记录退款单号。
- 定时任务：对 `pending` 订单主动查单，处理“回调丢失”和“回调先于本地订单落库”的乱序。

### 5.3 回调安全清单

- 微信 APIv3：校验 `Wechatpay-Timestamp`、`Wechatpay-Nonce`、`Wechatpay-Signature`，使用平台证书或微信支付公钥验签；AES-256-GCM 解密 `resource`。
- 支付宝：RSA2 验签，校验 `app_id`、`seller_id`、`out_trade_no`、`total_amount`、`trade_status`。
- 第三方：按其文档验签，并**主动查单二次确认**，不能只信回调。
- 幂等：订单号 + 渠道事件号唯一索引；已处理事件直接返回成功。
- 应答：微信 200/204；支付宝返回 `success`；处理失败返回非成功让渠道重试。
- 日志：不记录完整回调报文、证书、密钥、用户图片或视频。

### 5.4 权益发放

- 支付成功只入账“订单已支付”，权益发放单独一步，失败可重试。
- 权益与账号绑定，记录来源订单；退款时按规则扣回未使用次数，已使用部分按公示规则处理。
- 免费一次权益与付费权益分账管理，不能互相覆盖。

## 6. 合规与运营风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 无照经营 | 持续向公众收费属于经营行为，个人收款码不适用远程经营收款 | 办理个体工商户；保留订单、退款、发票记录 |
| 微信小微场景不符 | 官方明确仅线下行业，线上 AI 服务不在范围 | 不使用小微通道承接线上订单 |
| 支付宝当面付场景 | 产品定位线下扫码，网页订单转二维码可能被复核 | 个体户后改用电脑网站支付；当面付仅作补充 |
| 第三方通道 | 进件主体、资金路径、费率与关停条款不透明 | 只做小额内测；逐家核实协议与结算主体 |
| AI 内容合规 | 面向境内公众提供生成式 AI 服务涉及备案/安全评估；使用境外模型涉及数据出境 | 公开运营前单独评估，不把支付上线当成合规完成 |
| ICP 备案 | 微信 PC 网站支付要求域名已完成 ICP 备案 | 提前办理，备案期间不开放真实收款 |
| 发票与税务 | 个人可代开发票，个体户可自开；收入需申报 | 上线前确定开票口径与税负 |
| 风控冻结 | 新商户、异常交易、投诉可能触发限制 | 小额起步、及时退款、保留交付与沟通记录 |

## 7. 待确认问题

1. 目标用户是否只在中国大陆？若含海外，是否接受更高客单价以覆盖 MoR 固定费？
2. 是否愿意办理个体工商户？这是决定“官方通道”还是“第三方过渡”的分水岭。
3. 是否必须提供发票？个人代开与个体户自开的流程不同。
4. 内测阶段预计流水与客单价，是否值得为第三方通道支付开通费和月费？
5. 公开运营前的生成式 AI 备案与数据出境评估由谁负责、何时启动？

## 8. 建议的下一步

- 先做支付模块的**无通道实现**：订单表、状态机、Mock 回调、幂等与权益发放测试；保持真实收款关闭。
- 同时确认个体工商户办理地与经营范围，拿到执照后再申请微信/支付宝，避免在无主体状态下反复试错。
- 不在当前代码中接入任何第三方支付密钥；密钥只能在服务端环境变量中，且需先完成上述主体与合规确认。
- 办理主体与开户的具体材料、步骤、成本和时间表见[个体户与支付开户清单](2026-10-23-个体户与支付开户清单.md)。
