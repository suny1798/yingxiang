# 衣装自动随机与账号收藏

日期：2026-10-29。需求FR51／NFR06—09、T53，关联FR50／T52。任务步骤见[任务卡](../tasks/衣装自动随机与账号收藏.md)，实际状态仅维护在[05](../05-开发任务与验收.md)。

## 实现

- 进入／刷新采用全量Fisher–Yates随机顺序，sessionStorage仅记录上一轮首套公开ID以避免连续相同；初始四行、每次滚动两行继续沿用该轮顺序，筛选不新增重复。
- 详情新增心形收藏／取消，列表新增我的收藏、数量和卡片标记；可叠加现有筛选。收藏由Java本人会话与PG持久化，不放本机私有缓存，不混用作品收藏。
- 独立GarmentFavorites控制器清理账号旧世代、取消旧请求、写入串行、不乐观伪报，不自动重试未知写入，失败通过GET核对；访客主动操作才提示登录，登录不自动收藏或生成。
- Java Controller／Service／Mapper、V4及966项公开ID资源白名单；每次读写验证本人及Owner，mutation精确Origin／类型／大小／目录ID／维护门禁，复合主键和ON CONFLICT幂等。删除账号级联清除，取消收藏仅删除本人那条记录。
- 新增GET /api/garments/favorites与POST /api/garments/{id}/favorite；OpenAPI、前端生成类型与Java目录同步，原44条路由保留，新目录46条。离线业务仍关闭，未更换框架、SDK或模型。

## 数据与实际切换

正式前先在云PG随机受标记临时schema运行V1—V4和合成会话HTTP验证，退出清理。Docker引擎初始未运行，接口测试采用既有云连接的隔离schema，不触及正式业务行。

正式切换停止仅匹配本项目Jar及既有私有配置的API和Worker，使用原固定官方PG18 digest保存26表dump。首次工具tag的本机索引损坏导致失败，改用项目既有官方digest成功；V4仅加空表，旧表内容哈希（除Flyway新增版本记录）不变。媒体原脚本误传users层，已修正为卷根；5个文件与既有sealed备份完全一致，补齐到预V4联合备份并验证dump／文件SHA-256，未把0文件误报为媒体已备份。执行脚本、前指针、联合备份和结果留在当前私有批次。

API／Worker使用同一新Jar及原运行配置，ready200／Worker存活；最终只补合同错误码后再次打包并同版本重启。当前Jar和PID由backend/backups/M22-current.json定位，普通构建产物保留target/，运行Jar置于私有批次，避免Windows文件锁覆盖。PG已有新写入，不恢复旧SQLite；未清空权益、订单、unknown、预算或媒体。

PG联合备份兼容V3与V4，当前目标清单新增收藏表；旧SQLite来源没有收藏，导入时不伪造。未执行新的全量恢复演练，不宣称生产RPO／RTO或云PITR。
