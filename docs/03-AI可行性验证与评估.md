# AI 可行性验证与评估

制定日期：2026-10-22；更新日期：2026-10-23。本文为评估执行方案，真实结果另行记录。

公开模型能力及费用见[模型方案与费用核对](08-模型方案与费用核对.md)。2026-10-23用户已配置服务端密钥、批准总计最多5美元；首批失败后明确追加一次诊断，第二批已出画且用户确认上衣基本符合参考图。执行配置见[测试操作](09-首次真实模型测试操作.md)，首帧、结束及用量反馈见[接入验证记录](reports/2026-10-23-真实模型接入验证.md)。具体账单、三图更新及完整样本集仍未完成，S1不据单样本标记通过，不自动增加第三批。

## 1. 要验证的假设

| 假设 | 验证方式 | 不通过时 |
| --- | --- | --- |
| 单人上衣能稳定生成 | 固定服装、动作与评审量表 | 缩小服装范围或评估其他路线 |
| 目标区域网络可运行 | 从真实地区、设备和网络建立媒体连接 | 调整供应商/区域或暂缓该地区支持 |
| 时延与播放可接受 | 测首帧、动作延迟、换衣与停顿 | 排查链路，调整体验目标并记录原因 |
| 会话能有界结束 | 主动结束、后台、断网与令牌晚用 | 修改时限方案并查实际用量 |
| 费用可承受 | 限额调用与供应商用量对账 | 降低体验时长、人数或调整产品路线 |

指标阈值以设计主文档第5章为准。PoC 先确认核心可行性，正式可靠性与兼容性验收在 S5 补足；不能将少量 PoC 样本写成100次验证通过。

## 2. 开始真实测试的输入

- 可用供应商账户、服务端配置的密钥、当前模型权限与测试配额。
- 明确的本轮预算金额、告警和停止条件；不得因为文档写有价格就自行充值。
- 实际目标地区及网络，首批桌面浏览器、摄像头和测试人员。
- 有权使用的服装图片与自愿参与的成人；用户说明与数据路径已核实。
- 已核对的 SDK/模型版本、提示模板和令牌限制；独立测试配置优先。

密钥不写入本文、Git、截图或前端配置。条件缺失时可以准备样本清单、Mock、计时方案与最小验证工程；真实测试状态保持“未执行”。

## 3. 分步执行

| 批次 | 工作 | 停止条件/输出 |
| --- | --- | --- |
| P0 文档与本地检查 | 核对模型、限额、数据条款；验证图片处理与相机清理 | 账号不具备权限或条件不匹配时停止付费步骤 |
| P1 最小链路 | 先用1件纯色上衣，约10—15秒计划时长完成建连、出画、结束 | 无法出画、人物严重失真或停止异常时先排查，不批量测试 |
| P2 同会话更新 | 连续切换3图，测试快速选择、提交失败与恢复 | 不重建连接；记录提交时间与视觉出现时间 |
| P3 边界与账单 | 结束、后台、断网、重连、晚使用令牌、重复申请 | 本地轨道和模型用量分别检查；异常费用停止后续批次 |
| P4 效果评估 | 按样本矩阵完成20段计划60秒业务窗口的会话 | 记录实际可见时长、评分与严重问题，不假定每段有60秒生成 |
| P5 正式可靠性 | 在 S5 补足至少100次有效建连尝试和目标设备回归 | 输出分母、失败类别、分位数、实际消耗及验收结论 |

上表是执行顺序，不是已完成状态。每批次开始前估算剩余预算；一次测试发现明确阻塞问题时先修复，不为了凑样本继续消耗。

## 4. 样本与评审

服装样本共20件：纯色、印花、条纹、开衫、外套各4件。为每件分配 garmentId，记录类别、来源授权、尺寸、格式与限制；不把人体视频或未授权商品图片默认提交到仓库。

5名成人每人至少4件，确保20件都覆盖；每段包含正面、小幅转身、抬手。记录光照、背景、衣服与原穿着差异。测试不达标、取消或设备故障的样本保留分类，不能悄悄替换后只报成功结果。

两名评审独立评分，维度为服装还原、人物保留和时间连续性：

| 分值 | 统一含义 |
| --- | --- |
| 1 | 目标效果基本不可辨认或无法使用 |
| 2 | 明显错误频繁，主要任务难以完成 |
| 3 | 基本可辨认，仍有明显问题 |
| 4 | 大部分时间稳定，少量局部问题 |
| 5 | 当前测试条件下表现稳定、目标细节较好 |

按主文档门槛统计各维度均分及严重问题比例，同时列出逐样本结果。人物明显被替换、身体大范围扭曲、衣服消失等单独记严重事件及持续时间。评分分歧超过1分时讨论并保留原始评分与说明；小样本结果不能外推到所有体型、设备和网络。

默认不录制测试媒体。评审可现场实时观察并填写元数据；如需保存录像、截图或动作延迟测量素材，先取得额外明确授权，约定访问与删除时间，不加入 Git。

## 5. 指标口径

| 指标 | 计量规则 |
| --- | --- |
| 首帧时间 | 相机已就绪、应用进入 connecting 的单调时钟时间，到生成视频首个实际呈现帧；另记点击开始到出画的整体耗时及授权等待 |
| 首帧真实性 | 首个远端视频帧与“已看到服装变化”分别记录；后者需人工观察，不能以本地预览或首个原画帧代替生成效果 |
| 动作延迟 | 同时观察动作与结果，使用经验证的测量方法；RTT 仅作网络诊断；没有可靠测法时记录未测 |
| 换衣时间 | 记录图片提交、API接受、人工观察新衣出现三个时刻；换衣 P95 取提交到出现 |
| 有效播放 | 记录呈现帧率、停顿和掉帧，说明统计窗口；不能用摄像头请求帧率代替结果播放帧率 |
| 建连成功率 | 首个生成帧实际播放为成功；技术失败包括超时、上游拒绝、网络或播放失败；权限拒绝、主动取消单列 |
| 分母 | 测试前列明目标条件；输出全部尝试与分类，不能事后移除网络失败提高成功率 |
| 分位数 | 保存有效时长列表，P95 使用排序后的 nearest-rank（第 ceil(0.95n) 项）；小样本注明探索性结果 |
| 本地资源关闭 | 从结束动作到所有本地轨道 ended、视频解绑；与供应商停止和最后计费时间分开 |
| 成本 | 记录生成秒数、费率、重试和供应商实际用量；应用估计与账单差额单列 |

业务60秒窗口、用户看到结果的时长和供应商计费秒数是三种不同数据，不互相代替。

## 6. 预算与停止

按2026-10-22核对的Lucy VTON 3.6实时标准档 $0.02/秒估算，20次各生成60秒约 $24；Fast档为 $0.04/秒。均未含重试及其他开销，只是计算示例，不是本次预算。费率来源与提案见08。100次建连测试不一定每次持续60秒，需单独规划；重叠满足两组条件的测试可复用记录，不能重复计算成额外独立样本。

每轮记录批准的预算上限、已经发生的用量、潜在尾部费用和剩余额度。供应商预算硬限制未经实测时，只做少量受控调用，并预留在途连接费用。出现异常重复连接、无法结束或费用对不上时立即停发新令牌并排查；停止授权不等于已有连接瞬间停止。
